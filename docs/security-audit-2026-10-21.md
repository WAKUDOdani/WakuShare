# Аудит импорта, экспорта и автосинхронизации

[Документация](README.md) · [Как пользоваться](USAGE.md)

Дата: 21 октября 2026. Основа: WakuShare 1.3.3. Исправления включены в исходники WakuShare 1.3.4. Аудит охватывает исходники приложения, реально
доступные маршруты фонового процесса, зависимости и собранный Windows-пакет.

## Граница доверия

Чужой `.wakushare`, `.capshare` или `.wakupresets`, его имена файлов, JSON,
контрольные суммы и ссылки на ресурсы считаются недоверенными. SHA-256 подтверждает
совпадение байтов с декларацией, а не безопасность автора или содержимого.

Приложение не исполняет код из пакета. Установка ресурсов эффектов и активных
форматов требует отдельного подтверждения доверия с отменой по умолчанию. Это
нужно, поскольку настоящие эффекты CapCut содержат Lua/JS и конфигурации, способные
подключать код. Такая проверка не заменяется поиском подозрительных слов в скрипте.
Обычный перенос медиа и автосинхронизация не требуют такого диалога. Подтверждение
действует только для текущей операции, а не для всех будущих пакетов.

| Экспорт                   | Произвольная строка документа могла приводить к чтению постороннего локального/сетевого файла      | Ограничение типов внешних ресурсов, запрет сетевых ссылок, согласованные ссылки документов и записей каталога                           |

| IPC                       | Файловые команды не проверяли окно и frame отправителя                                             | Команды принимает только основной frame текущего окна; посторонние окна и подфреймы отклоняются                                         |
| Навигация                 | Ссылки могли передавать произвольную схему системному обработчику                                  | Только HTTP(S) без встроенных учётных данных; переходы окна, подфреймов и webview запрещены                                             |

| Экспорт при ошибке вывода | Ошибка назначения могла оставить поток источника ожидающим записи                                  | Ошибка выходного потока завершает текущую передачу и передаётся в обычный обработчик отката                                             |
| Упаковка                  | Оставались ненужные возможности запуска Node/инспектора и подмены ASAR                             | Отключены соответствующие Electron fuses; включены проверка ASAR и загрузка приложения только из ASAR; готовый EXE проверяется повторно |

Старые `.capshare` без таблицы SHA остаются поддержаны. Их нельзя объявлять
криптографически проверенными: сохраняются проверки ZIP, размеров, путей,
исполняемого содержимого и ссылок. Современные пакеты не получают это исключение.

## Зависимости и среда

- Electron: 42.11.18, точная версия и официальный дистрибутив с контрольными суммами.
- CPython: 3.14.8, официальный Windows embeddable package, фиксированный SHA-256.
- .NET runtime: 10.0.13, официальный Windows ZIP, фиксированный SHA-512 из Microsoft release metadata.
- Обновлены уязвимые зависимости приложения и инструментов сборки. Lockfile
  проверен с используемым в CI pnpm 10.19.0.
- `pnpm audit --prod` не сообщает известных уязвимостей. В дереве разработки
  остаётся одно предупреждение moderate для `sprintf-js` без доступного патча:
  цепочка `electron-builder → @electron/get → global-agent → roarr`. Этот модуль
  не входит в приложение и не обрабатывает пользовательские пакеты. Данное
  предупреждение не скрывается и не приравнивается к выполнению кода при импорте.

Базовый архив синхронизации остаётся закреплён в `runtime-lock.json`. При сборке
поверх него автоматически устанавливаются проверенные Python/.NET из
`runtime-security-lock.json`, затем проверяется итоговый индекс каждого файла.
Все 96 файлов worker, принятых DLL и вспомогательных модулей сохранены побайтово.
Обновление не компилирует DLL и не подключается к CapCut. У Python отключён поиск
пользовательских пакетов: разрешены только собственная стандартная библиотека и
папка `tools` приложения. Обновление среды выполняется при сборке приложения,
а не при каждом запуске или импорте пользователя.

## Проверки и скорость

Проверены обычные переносы проектов, несколько таймлайнов, старые архивы,
перенос пресетов с медиа/шрифтами/эффектами, дубликаты, резервные копии, откат,
отмена и изменение источника во время экспорта. Новые проверки используют инертные
данные: вредоносный код не исполнялся.

Отдельно проверены traversal/ADS/device names, Unicode и case collisions,
повторный manifest, ссылки/junction, поддельное расширение, отказ от доверия,
подмена ресурсов с пересчитанными SHA, чужие IPC frames, некорректные URI,
подмена дистрибутива и кеша среды, ошибки потока назначения.

Полный автоматический набор: 230 тестов; 8 прежних проверок, требующих живого
редактора или специального окружения, не запускались. TypeScript и ESLint проходят.
Для обновлённого Python совпали все 54 проверенные ctypes-структуры, включая
размеры, выравнивание и смещения полей. Проверены импорты продуктовых модулей,
Unicode-пути и протокол реального worker на .NET 10.0.13 в режиме планирования
без нативных команд. Это не новая живая приёмка импорта в CapCut.

На синтетических локальных данных, по медиане трёх запусков с чередованием порядка:

| Сценарий                                          | До      | После   |
| ------------------------------------------------- | ------- | ------- |
| Распаковка 6002 файлов, около 140 МиБ             | 5,61 с  | 3,97 с  |
| Предварительное чтение оглавления этого ZIP       | 0,001 с | 0,251 с |
| Полный импорт 300 пресетов с 130 файлами эффектов | 3,31 с  | 3,16 с  |

Это не обещание тех же секунд на любом диске. Время решения пользователя о доверии
и декодирования в CapCut не включено. Защита не добавляет нового полного сканирования установленной библиотеки,
дополнительного чтения всех медиа ради антивирусной проверки или новых таймеров
опроса. Потоковая проверка встроена в существующий перенос.

## Практические ограничения

Подтверждение доверия разрешает передать код эффектов CapCut; оно не делает этот
код безопасным. Проверки WakuShare не заменяют исправления самого CapCut, его
декодеров и ОС и не доказывают отсутствие неизвестных уязвимостей в этих компонентах.
Процесс с уже полученным доступом на запись от имени пользователя может менять
файлы приложения: ASAR integrity и хеши не являются заменой подписи издателя или
изоляции такого процесса. При конкурентной подмене каталогов другим локальным
процессом проверки путей Node не дают полноценной защиты уровня handle-relative IO.

Пользовательские проекты, конфигурация, квитанции синхронизации и исходные файлы
при аудите не изменялись. Автоматические проверки переносов выполнялись в
временных каталогах. Отчёт описывает кодовые и автоматические проверки; ограничения живой приёмки указаны выше.

# Выпуск Windows-версии

1. Указать новую стабильную semver-версию в package.json и описать изменения в
   CHANGELOG.md. Отдельно указать реально проверенные версии CapCut.
2. Запустить тесты, typecheck, lint и сборку. Проверить новый сценарий в CapCut
   на отдельной копии проекта, если менялась работа с его данными.
3. Закоммитить изменения. `pnpm release` проверит чистоту дерева, версию и
   создаст локальный тег `v<версия>`. Самостоятельно ничего не отправляет.
4. `git push origin main` и `git push origin v<версия>` запускают Actions.
5. Release workflow на Windows проверяет код, собирает x64 NSIS + portable,
   проверяет ASAR/источник обновлений и SHA-512 установщика в latest.yml.
   При успехе создаёт **черновик** GitHub Release с setup, blockmap,
   portable и latest.yml. Токен GITHUB_TOKEN используется только в CI.
6. Проверить установку и при следующих выпусках реальное обновление предыдущей
   установленной версии. После проверки опубликовать черновик в GitHub Releases.
   До публикации автоматический клиент новую версию не получает.

Для ручной сборки: `pnpm run build:win`; публикация выключена явным
`--publish never`. Репозиторий не содержит ключей подписи; Windows-сборки пока
без подписи издателя. Первый реальный цикл установки обновления возможен только
после наличия двух собранных версий и проверяется отдельно от unit-тестов.

Portable не заменяет себя автоматически. Не переиспользовать номер опубликованной
версии и не заменять бинарники под прежним тегом. Для исправления делать следующий
выпуск. Не публиковать latest.yml без соответствующего установщика и blockmap.

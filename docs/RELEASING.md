# Выпуск Windows-версии

[Документация](README.md) · [История изменений](../CHANGELOG.md)

## Подготовить версию

1. Указать новую стабильную semver-версию в `package.json`. Не переиспользовать номер опубликованной сборки.
2. Обновить `CHANGELOG.md`, создать `docs/RELEASE-<версия>.md`, поправить номер и прямые ссылки скачивания в `README.md`. Ссылки конкретного старого релиза всегда ведут на его собственные EXE.
3. Указать реально проверенные версии CapCut, изменения поведения и существенные ограничения. Отделять автоматические проверки от живой приёмки в редакторе.
4. Запустить `pnpm test --testTimeout=15000`, `pnpm run typecheck`, `pnpm run lint` и `pnpm run build:win`. Для изменений работы с данными провести согласованную проверку в CapCut на разрешённом проекте с полным сравнением сохранности.
5. Выполнить `pnpm run verify:package` для готовых файлов. При выпуске требуется `WAKUSHARE_REQUIRE_INSTALLER=1`: установщик, blockmap и `latest.yml` должны совпадать по версии, размеру и SHA-512. Упакованный runtime и Electron fuses также проверяются.
6. Проверить состав исходников и assets на личные данные и секреты. Закоммитить изменения, затем выполнить `pnpm release`: команда проверяет чистоту дерева и создаёт локальный аннотированный тег. Она не публикует релиз.

## Собрать и опубликовать

1. Отправить main и новый тег обычным fast-forward, без перемещения прежних тегов. По возможности использовать одну атомарную отправку main и тега.
2. Дождаться успеха **CI** и **Release Windows** на нужном commit. Release Windows независимо устанавливает зависимости, запускает проверки, собирает Windows x64 NSIS и Portable, проверяет упаковку и загружает artifact `wakushare-windows` в Actions.
3. Workflow не создаёт и не публикует GitHub Release автоматически. После проверки создать один черновик на точном теге и загрузить уже принятый комплект файлов:
   - `WakuShare-<версия>-setup-x64.exe`;
   - `WakuShare-<версия>-portable-x64.exe`;
   - `WakuShare-<версия>-setup-x64.exe.blockmap`;
   - `latest.yml`, `SHA256SUMS.txt`, `package-verification.json`.
4. Сверить remote sizes/digests с принятыми локальными файлами. При неизвестном результате загрузки сначала проверить черновик; не создавать дубликат и не заменять файл вслепую.
5. Проверить описание и ссылки, точный commit тега и успех независимой сборки. Установку и реальный цикл обновления проверять отдельно, когда они входят в приёмку; чтение updater feed не считать проверкой установки.
6. Опубликовать черновик как стабильный latest только после явного разрешения на выпуск и прохождения проверок. До публикации обычный клиент его не получает.
7. Без авторизации проверить страницу latest, доступность файлов, контрольные суммы и ленту настоящим провайдером обновлений. Чтение ленты не должно запускать установку.

Локальная сборка использует `--publish never`. GitHub credentials доступны только процессу публикации или CI, не приложению и не исходникам. Ключи подписи в репозитории отсутствуют; сборки пока без цифровой подписи издателя Windows.

## Среды запуска

`runtime-lock.json` закрепляет базовый архив модуля синхронизации и индекс его файлов. `scripts/explorer-runtime.mjs` получает и проверяет этот ввод. Можно указать `WAKUSHARE_RUNTIME_DIR` на локальный каталог того же базового runtime: хеши всё равно обязательны.

`runtime-security-lock.json` закрепляет официальные дистрибутивы Python/.NET и итоговый индекс. `scripts/runtime-refresh.mjs` обновляет только среды запуска при сборке и проверяет результат. Принятые worker, helpers и нативные модули не пересобираются. Пользователь не скачивает runtime отдельно при каждом импорте.

## Оформить описание

Название: **WakuShare <версия> - краткая тема выпуска**. Текст в `docs/RELEASE-<версия>.md` начинается с H1; в поле описания GitHub Release передаётся содержимое после H1, чтобы не дублировать заголовок страницы.

Порядок блоков:

1. Одно предложение о результате обновления.
2. Для архивных выпусков - ссылка на актуальную версию.
3. **Скачать**: прямые ссылки на setup и Portable этой версии с объяснением выбора.
4. **Что нового**, **Улучшения**, **Исправления** или **Безопасность** - только непустые разделы, заметные пользователю изменения.
5. **Важно**: совместимость, миграция или изменение поведения, если это нужно пользователю.
6. Раскрываемые **Совместимость и технические подробности**: реально выполненные проверки, ограничения, назначение служебных файлов.
7. Автор WakuShare, Telegram, авторство CapShare и MIT.

Не выдавать список коммитов за готовые release notes, не переносить новые гарантии защиты на старые бинарники и не обещать совместимость с непроверенными версиями CapCut. При чистом редактировании описаний меняются только название/текст: сохраняются теги, даты публикации, assets, контрольные суммы и назначение latest. Новый EXE ради оформления Markdown не требуется.

## Обновления пользователя

Portable не заменяет себя автоматически: пользователь скачивает новый EXE и полностью закрывает старый экземпляр через трей перед запуском. Установленная версия получает stable-обновления и устанавливает их по явному действию пользователя после файловых задач.

Не заменять бинарники под прежним номером. Для исправления приложения делать следующий выпуск. Не публиковать `latest.yml` без соответствующих установщика и blockmap.

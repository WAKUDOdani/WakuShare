# Адаптер WakuShare 1.3.31

Это исходники нового адаптера. `runtime-src` сохранён как исходная замороженная версия. Приложение 1.3.31 использует отдельный пакет `WakuShare-explorer-runtime-1.3.31-win-x64.zip`, зафиксированный в корневых runtime-lock.json и runtime-security-lock.json. Каталог исходников не является готовым runtime.

## Совместимость

Номер CapCut используется для диагностики и привязки IPC к конкретному процессу. Он не разрешает вызов адресов от другой версии. `tools/adaptive_symbols.py` читает PE-файлы установленного редактора, сопоставляет 20 внутренних интерфейсов по нескольким независимым признакам и проверяет именованные экспорты SDK. Нативный хост повторно проверяет небольшие участки загруженного образа. Полного сканирования кода внутри редактора в продуктовой ветке нет.

Зависимости проверяются по операциям: подключение, чтение, добавление, папки, переименование, перенос, удаление и восстановление. Неопознанный интерфейс блокирует зависимые операции до отправки команды. Это не гарантия совместимости с любым будущим изменением частных API. Текущая реализация требует ABI Qt 6.2.2; несовпадение показывается явно.

Проверено в живом CapCut 9.7.1.4203: добавление PNG и папок, повторное открытие проекта с 13 шкалами, переименование, перенос, новый независимый файл на старом пути, удаление неиспользуемой отсутствующей карточки и восстановление вернувшегося файла. Обнаружение всех 20 интерфейсов отдельно проверено на эталонных файлах 9.6.0.4097. Живую приёмку этой сборки на 9.6 и Windows 10 не проводили.

При неопределённом завершении команды автоматический повтор запрещён. Подтверждённые квитанциями операции могут завершаться отдельной полной сверкой только чтением. Общий источник в нескольких шкалах получает явный отказ изменения пути, если нельзя доказать независимость изменения. Удаление используемого источника вместе с клипами не допускается.

Ошибка необязательного обновления списка медиатеки не отменяет проверенный результат синхронизации. Предупреждение предлагает переоткрыть проект. Неопределённое обновление списка также не повторяется автоматически.

## Сборка приложения

Распакуйте приложенный runtime ZIP в отдельный каталог, установите зависимости корневого проекта и передайте абсолютный путь:

```powershell
$env:WAKUSHARE_RUNTIME_DIR = (Resolve-Path '.\runtime-input').Path
pnpm install
pnpm build:win
node scripts/verify-package.mjs
```

При отсутствии кеша зависимости загружаются с закреплёнными контрольными суммами. Проверяются индекс каждого файла и соответствие каждого нативного манифеста его DLL. При опубликованном теге сборка загружает закреплённый runtime из соответствующего GitHub Release. Для автономной сборки распакуйте тот же runtime и укажите абсолютный WAKUSHARE_RUNTIME_DIR.

## Изменение нативного адаптера

Использованы MSVC 14.44, Windows SDK, .NET 10 SDK и Qt 6.2.2 msvc2019_64; стандарт C++20. Не пересобирайте принятые или уже загруженные DLL под прежним именем. Создайте новый target, обновите привязку и манифест и соберите новый пакет runtime.

```powershell
cmake -S runtime-adaptive -B runtime-adaptive/artifacts/NativeExplorerObserveBuild -G 'NMake Makefiles' -DCMAKE_PREFIX_PATH='C:/Qt/6.2.2/msvc2019_64' -DCMAKE_POLICY_VERSION_MINIMUM=3.16
cmake --build runtime-adaptive/artifacts/NativeExplorerObserveBuild
dotnet build runtime-adaptive/src/CapSync.Cli -c Release
```

Эксперименты проводят только на отдельном согласованном проекте: исходный снимок, одна команда, полная сверка и проверка после штатного сохранения. Не подключайте отладчик к живому редактору. Диагностические Probe, DraftAudit и тестовые исполняемые файлы не входят в продуктовый пакет.

Для блокировки кеша адресов используется Windows CRITICAL_SECTION, чтобы не зависеть от новой реализации std::mutex при загрузке старой библиотеки Microsoft C++ из CapCut.
